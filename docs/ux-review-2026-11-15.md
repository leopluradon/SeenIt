# SeenIt UX review — 2026-11-15 (v1.221, commit 07a5355)

A to-do list of user-experience problems, written for a model (or person) to pick up and fix.
Accessibility was deliberately out of scope (small, known user base). Each item says what's wrong,
how it was seen, where the code is, and a suggested fix. Line numbers are as of commit 07a5355 and
may have drifted; search for the quoted code if they don't match.

## Status

- **Sections 1 and 2: fixed** (2026-11-16, the commit that adds this file). Notes on how: the tab bar now
  shows up to 900px; the desktop nav measures itself (`seenit.navFit`) and folds what doesn't fit into a new
  "More" menu, which also links Goals, Library, Duplicates and the rest; Back closes dialogs and the long-press
  sheet (`seenit.dialogHistory`); the watch endpoints return `WatchedResult` (play ids, left-watchlist) so every
  "Watched …" toast has Undo; rating changes have Undo; the show page leads with "Watched SxxEyy" (S01E01 when
  not started); season pages are compact on phones and open at the next episode. 2.2's "move bulk actions into a
  ⋯ menu" was done as demoting them to secondary buttons instead.
- Sections 3–9: not started.

## How this was checked

- All of `src/SeenIt.UI` and `src/SeenIt.Mobile` were read.
- v1.221 was run as an isolated scratch copy (own database, localhost only) and driven with headless
  Chromium at phone (Pixel 7, 412px), tablet (744/820/852px) and desktop (900–1920px) widths, with
  three seeded test members.
- Aggregate counts (no titles or personal data) were read from the live database to see which
  features the five members actually use. Its activity log only covers 2026-11-02 to 2026-11-15.
- **Not tested on real hardware:** the Android app, the iPhone home-screen app, push notifications,
  live Jellyfin/Plex/Kodi playback. Android notes below come from reading code.
- How to reproduce this setup (throwaway browser image + scratch instance on 127.0.0.1:8092) is in
  the session memory note "SeenIt UI testing on the homelab". Never test against the live app on :8082.

## Ground rules for whoever fixes these

- Follow the repo's existing conventions: plain-English UI copy, comments explaining *why*, undo
  toasts rather than confirm dialogs where the action is reversible.
- Build `src/SeenIt.Web` and run `dotnet test` before committing. Deploy per the usual steps.
- Check each fix at 412px (phone), 820px (iPad portrait) and 1440px (desktop).
- Items are independent unless noted; do them in priority order (section 1 first).

## 1. Broken or misleading — fix first

### 1.1 No navigation at all between 761px and 900px wide
- **Seen:** at 820px (iPad portrait), 852px (phone landscape) and 900px the header shows only logo,
  search, share, bell and avatar. No top nav, no bottom tab bar.
- **Cause:** `src/SeenIt.UI/wwwroot/seenit.css:634` hides `.topnav` at `max-width: 900px`, but the
  tab bar (`.tabbar`, hidden at `:133`) is only shown inside the `max-width: 760px` block (~`:639–651`).
  The phone layout tweaks (main padding for the tab bar, toaster position) are also in the 760 block.
- **Fix:** show the tab bar (and the padding/toaster offsets that go with it) up to 900px, i.e. move
  those rules into the 900px block, or make both breakpoints the same.

### 1.2 Desktop top nav silently clips links below 1280px
- **Seen:** at 1024px, Lists, Stats and Friends are cut off; at 1180–1279px Friends is. The nav
  strip scrolls sideways with its scrollbar hidden, so nothing shows that more exists.
- **Cause:** `seenit.css:99` (`.topnav { overflow-x: auto; scrollbar-width: none }`) competing with
  the search box for width.
- **Fix:** collapse overflowing links into a "More ▾" menu (or fold rarely used ones into it at
  narrower widths), and/or shrink the search box to an icon below ~1200px.

### 1.3 Goals, Library, Duplicates (and more) are unreachable on desktop
- **Seen:** the phone "More" page (`src/SeenIt.UI/Pages/More.razor:41`) lists For you, Pick for me,
  Library, month/year review, Goals, Customize tabs and Duplicates. On desktop there's no link to
  `/more`, and the top nav + account menu (`src/SeenIt.UI/Layout/MainLayout.razor:19–64`) don't
  include those. Goals appears on Home only once a goal exists; Library and Duplicates have no
  desktop entry point at all.
- **Live data:** 0 goals, 0 library entries.
- **Fix:** add a "More" item to the desktop nav/account menu linking to `/more`, or add the missing
  pages to the account menu.

### 1.4 Back leaves the page instead of closing a dialog or bottom sheet
- **Seen:** with the "When did you watch…?" dialog open on a movie page, browser Back navigated to
  the previous page. Same with the long-press bottom sheet. The Android back button uses the same
  history, so it behaves the same in the app.
- **Code:** `src/SeenIt.UI/Components/Modal.razor:34` (registers with `seenit.dialogOpened`),
  `ContextMenuHost.razor`, `seenit.js` `dialogOpened`/`dialogClosed`.
- **Fix:** when a dialog/sheet opens, push a history entry (e.g. `history.pushState({dialog:id})`);
  on `popstate` close the top dialog instead of navigating; when it's closed normally, go back one
  entry quietly. Watch out for the scroll-restore code in `seenit.js` (popstate handler) and for
  Blazor's own navigation interception.

### 1.5 Rating pips keep showing a cleared rating on touch screens
- **Seen (phone, real touch taps):** tap pip 7 → saved 7. Tap 7 again → toast "Rating removed",
  server has no rating, but the pips still show 7 until you tap elsewhere.
- **Cause:** `src/SeenIt.UI/Components/RatingPicker.razor:30/44` — `@onmouseenter` sets `hover`
  on touch, and nothing clears it (no mouseleave on touch), so `hover ?? Value` keeps showing 7.
- **Fix:** set `hover = null` in `Pick` (and in the stars variant); optionally ignore mouseenter for
  touch pointers.

### 1.6 Uploading after the page sat idle for an hour signs you out
- **Cause:** `src/SeenIt.UI/Services/ApiClient.cs:565` skips the refresh-and-retry for
  `MultipartFormDataContent` (the stream can't be re-sent), then signs out on the 401. Access tokens
  last 1 hour (`src/SeenIt.Server/Program.cs:36`).
- **Seen (confirmed in real time):** signed in, left Settings open and idle for 61 minutes (the page
  only polled `api/auth/features`, which needs no token, so nothing renewed the session), then
  uploaded a profile picture: `POST /api/auth/avatar` → 401, toast "Please sign in again", sent to
  the login page with the stored tokens wiped. The 90-day refresh token was still valid, so this
  sign-out was unnecessary.
- **Affects:** avatar upload (`Settings.razor` UploadAvatar) and imports (`UploadImportAsync`).
- **Fix:** before any multipart upload, refresh the token if it's expired or close to expiry
  (TokenManager already knows `_expires`); or buffer the body so the request can be rebuilt and
  retried once like other requests.

### 1.7 On phones the "Watched …" toast covers the "Rate it?" strip
- **Seen:** after marking a movie or episode watched, the toast sits on top of the rating prompt
  for ~3s (both centred just above the tab bar).
- **Code:** `seenit.css:652` (`.toaster` bottom) and `:1174` (`.rate-prompt` bottom).
- **Fix:** when the rate prompt is open, stack the toaster above it (e.g. a body class that raises
  `.toaster`), or fold the "Watched" message into the prompt itself.
- **Related:** the episode page always asks to rate the episode (`Episode.razor:197`) even when
  episodes are switched off for "To rate" (Settings → Ratings, `UserPrefs.RateKinds`). Respect that
  setting (default: movies and shows only).

## 2. Everyday episode tracking takes too many steps

### 2.1 A show you haven't started has no "watched episode 1" action
- **Seen:** a not-started show page offers only "Mark all watched". The next-episode row only
  appears once there's progress (`src/SeenIt.UI/Pages/Show.razor:119`, `@if (s.Progress is { } p)`).
  On a phone, Seasons is 1.8 screens down, then you open the season and find episode 1.
- **Fix:** when there's no progress but aired episodes exist, show "Start: S01E01 ✓" in the same
  panel. (The API already knows it: `ItemStatus.NextEpisode` returns S01E01 for unstarted shows.)

### 2.2 The primary button on a show in progress is "Mark all watched"
- **Seen:** for a show 5 of 14 episodes in, the big red button is "Mark all watched" next to "Mark
  unwatched"; "Next: S01E06 ✓" is a screen further down on phones.
- **Fix:** make "Watched S01E06" the primary hero action when there's a next episode; move "Mark all
  watched" and "Mark unwatched" into a secondary/⋯ menu.

### 2.3 Season pages are very long on phones
- **Seen:** episode cards average ~410px tall (full-width still + overview). At 5/14 watched the
  first unwatched episode was 3.2 screens down; the page opens at the top.
- **Code:** `src/SeenIt.UI/Pages/Season.razor:91` (`.episodes` list).
- **Fix:** on phones use the compact row list the episode page already has (`SeasonEpisodes`
  component) or a smaller thumbnail beside the text; scroll to (or highlight) the first unwatched
  episode on open.

### 2.4 Marking watched has no Undo
- **Seen:** the "Watched X" toast has no Undo on the movie page and Progress; same code path in Up
  next (`UpNextCard.razor:43`), Progress (`Progress.razor:304`), movie (`Movie.razor:205`), the
  long-press menu and the Android widget. Removing plays does have Undo.
- **Fix:** have the watch endpoints return the created play id(s) and offer Undo that deletes them
  (`DeleteHistoryAsync`). Bulk marks (season/show/up-to-here) too.
- **Also:** changing an existing rating (e.g. 8 → 3 by a slipped tap) has no Undo
  (`Movie.razor:242` and equivalents). Offer Undo back to the previous value when one existed.

### 2.5 "✓ Watched" adds another play rather than toggling
- **Seen:** on a watched movie the green "Watched" button opens "When did you watch…?" and adds a
  play. All five members use "Ask", so nothing is logged silently, but the label is misleading.
- **Fix:** label it "Watch again" (the episode page already says "Watched · watch again").

### 2.6 The date dialog leads with "Right now" even for bulk marks
- **Code:** `src/SeenIt.UI/Components/WatchDialog.razor:14`.
- **Live data:** of 162 bulk marks with a recorded date choice, 71 used release dates or "unknown".
- **Fix:** for `Bulk`/`Through`, make "Release dates" the primary (first, red) button. Add a
  "Yesterday" option (the long-press menu already has one).

## 3. Missing bulk tools

### 3.1 Up next / Progress keep every unfinished show forever
- **Code:** `src/SeenIt.Server/Services/TrackingService.cs:1018` — every show with a next episode
  and status Watching, no age cut-off.
- **Live data:** 105 show-status changes in two weeks (93 to Dropped), 43 by one member in a single
  day — members are cleaning up one show at a time.
- **Fix:** add a Select mode on Progress (like History's) with bulk Pause/Drop; and treat shows with
  no play in 6–12 months as "stalled" (hidden from Up next, shown in their own Progress group, one
  tap to resume). Stats already has a "stalled = no episode in 6 months" notion (`MoreStatsService`).

### 3.2 Ratings has no multi-select
- **Live data:** one member removed 359 movie ratings by hand in 18 minutes (2026-11-14).
- **Fix:** Select mode on Ratings with bulk remove (and Undo).

### 3.3 Imports commit immediately
- **Live data:** 10 imports, 4 "clear data" runs, 2 import undos in two weeks — a retry loop.
- **Fix:** a preview step ("this will add N plays, M ratings, K watchlist entries; X unmatched") before
  committing; and an alert/push when a long import finishes (currently only the Settings page polls).

## 4. Finding things

### 4.1 Posters never show whether you've seen it or it's on your watchlist
- **Seen:** Discover and Search show no seen/watchlist marker; Discover → Top rated was a page of
  titles already logged, unmarked. Same for "You might also like" and trending rows.
- **Cause:** `MediaSummary` (`src/SeenIt.Contracts/Dtos.cs:342`) has no user-state fields.
- **Fix:** add optional `Watched`/`OnWatchlist` (and maybe `Rating`) to `MediaSummary`, fill them
  server-side for signed-in users (one query per page of results), and show a small ✓ / bookmark badge
  in `PosterCard`. Optionally a "Hide watched" chip on Discover.

### 4.2 Search stops at 20 titles
- **Code:** `src/SeenIt.UI/Pages/Search.razor:174` loads page 1 only; there's "Show more" for people
  but not titles.
- **Fix:** add "Load more" for titles (the API already takes `page`).

### 4.3 Discover forgets where you were
- **Seen:** after "Load more" twice (57 titles) and opening one, Back gave 19 titles at the top.
- **Code:** `Discover.razor:56` clears items in `OnParametersSetAsync`.
- **Fix:** keep the loaded page count in the URL (`?pages=3`) or cache the list in a scoped service
  so Back restores it; then scroll restore works. Consider genre/year/service/hide-watched filters.

### 4.4 Nothing reveals the long-press / right-click menu
- It does almost everything (rate, mark, watchlist, lists, pause/drop…) but has no visible cue.
- **Fix:** a small ⋯ button on cards/rows that opens the same menu, or a one-time tip.

### 4.5 Filters are lost on Back
- **Seen:** Progress tab ("Caught up" → back to "Watching"), Watchlist type, Ratings score chip and
  Calendar date window all reset after opening an item and pressing Back. History keeps its filters
  because they live in the URL.
- **Fix:** put these in the query string the way History does (`Nav.NavigateTo(..., replace: true)`).

### 4.6 Calendar opens three days in the past and forgets settings
- **Code:** `src/SeenIt.UI/Pages/Calendar.razor:82` (`from = Today.AddDays(-3)`).
- **Seen:** on a busy calendar the "Today" heading was below the first screen (y≈948 on a phone).
  Month view and "Hide watched" reset when you come back.
- **Fix:** start at today (or scroll to Today on load); remember view and chips (URL or prefs).

### 4.7 Friends defaults and Find
- `/friends` opens on Following, not Activity (`Friends.razor:111`). Make Activity the default.
- Find silently ignores a one-letter query (`Search()` returns when length < 2). Show a hint, or
  with five members just list everyone under Find.

### 4.8 Home order buries Up next
- Default order (`Dtos.cs:228` `UiPrefs.HomeSections`) puts On this day, the review banner and Goals
  above Up next; on a phone Up next started ~600px down. Move "upnext" to the top of the default
  order (existing users keep their saved order).

## 5. First run

- After registering, new members land on Settings with a paragraph about imports
  (`src/SeenIt.UI/Pages/Register.razor:108` → `settings?welcome=1`), then a Home that says
  "Nothing yet". Empty Progress, Watchlist, Lists and Stats pages explain but have no button.
- **Fix:** land on Home with a dismissible 3-step "Get started" card: find a show/movie you're
  watching (link to Discover/Search), import from Trakt/Letterboxd/etc., follow friends. Give the
  empty states a button (e.g. Watchlist → "Browse Discover", Progress → "Find a show").

## 6. Actions that are too easy to trigger

- **Delete list** has no confirmation and is gone once the 7s Undo toast fades
  (`src/SeenIt.UI/Pages/ListPage.razor:299`). Add a confirm (it's destructive and the button sits
  next to Edit). **Unwatch season** and **Sign out** (More page) are also instant — at least confirm
  sign-out on the More page, where it's a big full-width button.
- **A second quick tap falls through a closing sheet:** double-tapping "Right now" logged one play,
  then the second tap landed on the Recommend dialog underneath. Ignore taps for ~300ms after a
  dialog closes, or close with a short fade that blocks pointer events.
- **Header Share button shares private pages:** on History, Stats, Watchlist, Review and Settings it
  shares a link that just shows the recipient their own page (`MainLayout.razor:161` `SharePage`).
  Hide it on those pages, or share the public profile equivalent (`u/<name>/history`, etc.).

## 7. Clutter

- Title pages (and posters) give prime space to features with zero live use: **Own it** (0 library
  entries), **Private note** (0 notes), the poster **Not interested ×** (0), **Check in** (0 in the
  log), rewatch mode (0). Lists has Saved and Browse tabs but all 17 lists are private.
  **Fix:** move these behind a ⋯ menu on title pages, or make them opt-in in Settings (Private notes
  already has a toggle; the × already has one too — consider defaulting it off).
- On phone title pages "Your rating" and "Private note" come before the synopsis and Where to watch.
  Put synopsis/where-to-watch first on phones, or collapse the note to a one-line link.

## 8. Smaller polish

- Rating pips are 12–15px on phones (`seenit.css:399` compact = 12px); the long-press sheet uses 22px.
  Use ≥20px touch targets on phones.
- Review page "peak viewing hour: 8 am" ignores the 24-hour clock setting
  (`src/SeenIt.UI/Pages/Review.razor:225` `HourLabel` hard-codes "h tt"). Use `Fmt.Prefs.Clock24`.
- Not-found pages (bad movie id, unknown member) show "Retry"; show "Go home"/"Search" instead.
- Day headings repeat the date: "Thursday, Nov 12 Nov 12" (Calendar, Alerts). Drop the second date
  when the first already includes it.
- The website stays on "Can't reach the SeenIt server" after the connection returns until you tap
  Retry. Retry automatically on `online` event / when a later request succeeds.
- Settings → Display is ~8 phone screens long; consider splitting (Appearance / Scores / Layout).
- Change password has no "confirm new password" field. Email and username can't be changed
  (`AuthEndpoints.cs` PUT /me only sets DisplayName).

## 9. Gaps (feature ideas, lower priority)

- "My streaming services" setting to filter Where to watch, Pick and the watchlist.
- Log one play for several members ("watched with …"). Pick for a group exists; logging together doesn't.
- A way to reply to/react to a recommendation (9 sent, no reply path).
- Friends-only or shared lists; adding titles from the list page itself (currently only from title pages).
- A light theme (all seven are dark); a keyboard shortcut for search ("/").
- Android (from code): the widget's ✓ ignores your Up next sort order and shows Progress's first 4
  (`src/SeenIt.Mobile/Platforms/Android/UpNextWidget.cs:96` area, `ProgressAsync()` unsorted);
  App Links (`MainActivity.cs:15` `DataPathPrefixes`) don't cover `/review`, `/goals`, `/compare`,
  `/library`, `/settings`.

## What's already good (don't regress)

Fast in-app navigation (~0.2s locally), scroll restore on Back for most pages, forgiving imports
with match checks and undo, undo on nearly every removal, spoiler blurring, saved views on History,
the long-press menu itself, clear empty-state copy.
